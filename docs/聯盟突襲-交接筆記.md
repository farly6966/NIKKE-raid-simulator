## 2. 使用者要做什麼

**公會（32 人）的聯盟突襲排班表。**

他手上已經有一份 Excel（`工作表2 (排序)`），長這樣：

| 名称 | 同步器等级 | 水 | 电 | 风 | 火 | 铁1 | 铁2 |
|---|---|---|---|---|---|---|---|
| 藤原妹洪 | 698 | 1 | | 1 | 1 | | |
| KE32 | 774 | 1 | | 1 | 1 | | |

格子裡的 `1` = 這個人要打這隻王，空白 = 不打。**他要的是把那個 `1` 換成實際算出來的傷害。**

流程：成員各自匯出 JSON → 會長一次全部拖進網站 → 每隻王排好一套隊 → 算 → 出分配表 → 下載貼回 Excel。

### 王的數量是 6 不是 5

聯盟突襲有五隻王（五屬性各一）。**全部階段打完後，第五隻王會進入「無限階段」（血量無上限），那時全公會只能打那一隻。** 所以排班表上第五隻王佔兩欄（他表上的 `铁1`/`铁2`）。每一期第五隻王的屬性都不同。

```

GetMyGuildInfo   → 不存在
member_id        → 不存在
```

```js
function bossDefaults(sid) {
  const all = (U().bossDefaults ||= {});   // 使用者自己的儲存，預設是空的
  return (all[sid] ||= {});

```

整份 app.js 只有兩個內建值：`def: 31784`、`core_px: 0`。**防禦力、核心大小、階段區間全部是使用者自己填**，再靠「分享 Boss 設定」代碼互傳。所以那邊沒有數值可以抄。

### 它有的、可以參考的東西

⚠️ **他們註解裡留的雷**：表裡存的是「**Boss 自己的屬性代碼**」，不是官方公告圖上的「弱點」。公告寫的是「用這個屬性打牠」，兩者相反。他們曾經整組填反。

### 它跟本 repo 幾乎確定是同一個作者的產物

`app.js` 通篇韓文註解，語氣和格式跟本 repo 的 `union-raid.ts` 一模一樣（「실측 2026-08-28」「(유저 결정)」這種寫法），頁面上也掛著 `Jgaram/nikke-calc` 連結。

**但它的 bundle 沒有宣告授權。** 看設計、重新實作沒問題；整段複製有風險。

### 美術館（MUSEUM HALL）是完全不同的模式

它有一張 `level_stats.def`（等級 0–1200 → 防禦力）表，但那是**美術館三隻王專用的 group 230000**，不能套到聯盟突襲。已經確認過，別再往這條路走。

唯一有用的副產品：**防禦力 31,784 = 敵人等級 400**（單人突襲基準）。

## 4. 已經做完的東西

### 資料進來的路

| 檔案 | 做什麼 |
|---|---|
| `site/src/exia-import.ts` | **Exia 匯出檔 → 計算機規格**。新舊兩種格式都吃 |
| `site/src/exia-import.test.ts` | 19 條測試，含 3 條釘住「cookie 不外流」 |
| `scraper/profile_import.py` | 同一件事的 Python 版（本機批次用） |

**Exia = ExiaInvasion R**，一個 Chrome 擴充功能，從 blablalink 匯出自己帳號的養成資料成 `<名字>_<uid>.json`。

**設計原則（重要）**：`exia-import.ts` **只翻欄位名**，翻譯規則一律交給既有的 `blablalink.ts` 的 `areaToOverrides` / `consoleFrom` / `synchroFrom`。那三個函式一行都沒改。理由：樂島 CSV、blablalink、Exia 三條路要落在同一個位置，不然同一個帳號會算出三種規格。

**兩個必須換算的坑**：
1. **數值差 100 倍**：blablalink 給 `1802` 代表 18.02%，Exia 直接給 `18.02`。合成 `state_effects` 時要先 ×100
2. **超載選項要合成 id**：blablalink 是「裝備欄存 id、另一張表查效果」，Exia 把效果寫在裝備欄裡。要替每種（效果, 數值）發流水號再組回那張表，**從 1 開始**（0 在那邊代表空欄）

**兩種 Exia 格式**（沒有版本號，靠鍵名分辨）：

```
新（2026-08 起）  equipments: { head: { tier, lv, options: [[線],[線],[線]] }, ... }
                  recycleRoomResearches: { "1001": { Level: n }, ... }
                  有 cube_id / cube_level / attractive_lv

舊（~2026-09-02） equipments: { "0": [線, 線, 線], ... }   ← 0/1/2/3 = 頭/身/手/腳
                  researchLevels: { general: n, attacker: n, ... }
```

**憑證處理**：匯出檔裡有 `cookie`（含 `game_token`）和 `game_uid`。程式從頭到尾不讀。另外有 `stripExiaProfile()` 給使用者在**傳檔之前**洗檔用（白名單，不是黑名單），順帶把 489KB 縮到 103KB。

### 畫面

| 檔案 | 做什麼 |
|---|---|
| `site/src/union-squad.ts` | 視覺排隊器：五格 + 角色格柵（搜尋 + 屬性/職業/爆裂篩選） |
| `site/src/union-raid.ts` | 聯盟分頁主體。匯入、王的盤面、執行、分配表 |

**為什麼另寫排隊器而不共用計算機的**：`ui.ts` 的 `renderSquad` 是 248 行，牽連 15 個閉包（`renderEditor`、`renderCharacterSettings`、`openCharPanel`、`saveState`…），抽出來等於對 app 核心動手術。而**聯盟的隊伍只需要五個名字** —— 養成全部來自各成員的檔案，在這裡放養成編輯器反而是誤導。樣式沿用既有的 `.roster-*` 類別。

**角色格柵只有一個**，會移動到「正在編輯的那一列」下面。⚠️ 掛 DOM 的動作必須在 `renderSlots` 裡做，不能在 `open()` 裡 —— 因為開啟後馬上會整塊重畫，在 `open()` 掛的會被扯掉。有測試釘住。

### 分配表

`buildGrid()` / `gridToCsv()`（都在 `union-raid.ts`，純函式好測）

- 列是人、欄是王，依**總貢獻**排序
- **空白分兩種**：沒指派（格子不存在）vs 指派了但缺角色（寫出缺誰）。填 0 會被讀成「打了但零傷害」
- CSV **帶 BOM**，不然 Excel 開中文會亂碼
- 數值是**原始整數**，寫成「億」Excel 會當文字，不能加總排序
